### 1. Meta Muse Glimmer 30B — The First Frontier-ish Local Agent Model
**What it is:** Meta released Muse Glimmer, a 30B dense multimodal model under Apache 2.0, explicitly designed for always-on local agent workflows. At 4-bit quantization it fits under 20GB — meaning it runs on a single RTX 3090 or M-series Mac. Supports 100+ languages, interleaved image+text inputs, controllable reasoning effort, and tool use out of the box. Companion Muse Spark 1.2 open weights are coming soon. Frameworks: Ollama, LM Studio, llama.cpp, MLX, vLLM all planned.

**Why it matters:** This is the moment local AI became viable for agent-grade work — not just chatting, but long-horizon tasks, tool calling, and always-on background agents. The model was trained from the start on agentic traces (not a "base then post-train" release), making it qualitatively different from prior open weights. Clement Delangue said "Meta is back." For the audience: you can now run a capable agent loop locally, offline, no API bill.

### 2. Anthropic Managed Agents: Decoupling the Brain from the Hands
**What it is:** Anthropic Engineering published "Scaling Managed Agents: Decoupling the brain from the hands" — their framework for running large-scale agent systems by separating the reasoning model (the brain) from the tool-executing environment (the hands). The brain decides what to do; the hands are lightweight, stateless, and parallelizable.

**Why it matters:** This is the design pattern the industry is quietly converging on for production agents, but most people building with AI still think of agents as one big model doing everything. Understanding brain/hands separation explains why some agent setups scale and others don't — and it directly changes how you architect anything involving multiple AI steps or tools.

### 3. Cursor Router: How AI Picks the Right Model Per Task
**What it is:** Cursor published how their internal model router works — a learned system that automatically routes each code completion, edit, or chat message to the most appropriate model (cost, latency, capability tradeoff) without the user choosing. They also dropped "Mixture-of-Kittens," their open-source MoE megakernel for NVL72 inference clusters, and a detailed writeup on their cloud agent environment setup.

**Why it matters:** Most people still manually pick a model ("should I use Sonnet or Opus for this?"). Cursor's answer: don't — the router should handle it. This signals where the industry is going: smart defaults, not menus. For the audience: understanding how routing works demystifies why Cursor feels "fast and cheap on simple stuff, powerful when needed."
