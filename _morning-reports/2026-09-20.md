## Top 3 Things Worth Paying Attention To

### 1. Jev sparked a "decision model" moment — and 6 open-source clones in 2 days

**What it is:** Jev is a non-generative discriminative model that launched to 36M views (comparable to Anthropic's Fable 5.1 launch at 57M). It's positioned as a fast "System 1" complement to LLMs: instead of generating text, it scores and selects among options. Braintrust already integrated it as an eval model at ~400x lower cost than LLM-based scoring. Six open clones appeared within two days: Bespoke Nimble (LoRA on Qwen3.5-9B, 90% vs Jev's 93% on its benchmark), Kev-0.5B (runs on a MacBook Pro), SemIf/OpenJev, DiffusionGemmaJev, Laya, and Jevlike. The synthetic-data-only training approach is underreported.

**Why it matters:** The most interesting framing came from practitioners who weren't impressed by the chat angle but immediately saw the workflow-control-plane use case: routing, escalation, citation selection, notification filtering, UI adaptation. LangChain's Harrison Chase called browser-use the strongest application he'd seen — not chatbot interactions. This is the clearest example yet of AI system design splitting into "generative for reasoning, discriminative for control." For anyone building multi-step workflows, a tiny, locally-runnable decision model that handles routing cheaply is a different primitive than anything available last year.

**Format:** Explainer

**Reel angle:** "Everyone's building with ChatGPT. This week, something quieter launched that might actually change how AI systems are built — it doesn't generate text at all"

### 2. AGENTS.md is now a real cross-tool standard

**What it is:** Claude Code v2.1.277 now checks for AGENTS.md when no CLAUDE.md is present, with config-level toggle support. Simon Willison immediately flagged the practical impact: fewer shim files that just point one config format to another. AGENTS.md originated as OpenAI's agent instruction file format; Claude Code picking it up makes it the first cross-tool agent configuration convention with two major coding agents behind it.

**Why it matters:** Anyone running AI coding assistants across multiple tools (Claude Code, Cursor, OpenAI Codex-style agents) now has a single file they can drop in a repo that works across the stack. This is a small but meaningful shift in how people will set up new projects. For anyone setting up AI-native repos, AGENTS.md is now the practical default — not a workaround. The meta-point: tooling standards in the agent layer are consolidating faster than most people realize.

**Format:** Tip

**Reel angle:** "There's now one file you can add to any repo that tells every major AI coding tool how to work in it — and most people don't know it exists"

### 3. The "Harness Tax" paper put numbers on what practitioners already knew

**What it is:** An empirical study ("An Empirical Study of Harness Design for Coding Agents") showed that a minimal tool set — read, write, edit, bash — reaches the Pareto frontier on benchmark performance while reducing unnecessary spend. Benchmark outcomes are increasingly shaped by harness structure, context setup, turn budgets, and tool affordances, not the base model. Corroborating real-world data: one team documented cutting knowledge-base pipeline spend by ~two orders of magnitude since spring by routing Opus → Sonnet → GLM 5.3 Flash for execution tasks. A separate practitioner described a stack using GPT 5.6 Sol XHigh for planning, GLM 5.3 Flash for implementation.

**Why it matters:** The "which model" question has a ceiling. The "how do I structure the harness and route correctly" question has room left. The bifurcation pattern — frontier models for planning, cheap models for execution — is now documented in production, not just theorized. For Mansi's audience, this is the unlock that goes from "I pay $X/month for Claude" to "I have a workflow that costs 10x less and works better."

**Format:** Shift

**Reel angle:** "The people cutting their AI costs by 100x aren't using cheaper models — they're restructuring how tasks get routed"
