## Top 3 Things Worth Paying Attention To

### 1. ChatGPT Work is not a chat upgrade — it's a full agent runtime
**What it is:** Simon Willison's deep-dive (Aug 30) reveals ChatGPT Work is two distinct products under one confusing name. The cloud version (Work Cloud) ships features that don't exist in Chat: code execution *with open internet access*, a persistent cross-session filesystem, a full headless Chrome browser, the ability to publish live websites on Cloudflare Workers (ChatGPT Sites), and scheduled prompt automations. Work sessions draw from the Codex compute allowance, not the Chat allowance. OpenAI explains it in terms of *use cases* ("tasks with clear outcomes") rather than the *technical capabilities* it adds — which is why most users don't know what they're actually getting.

**Why it matters:** The code execution + internet access combo is the real unlock: you can clone a GitHub repo, install dependencies, then have the agent interact with live APIs — all in one session. Claude's equivalent container allows restricted access (PyPI, NPM, GitHub only); Work is open by default. This is the feature that separates "chat with an AI" from "delegate a task to an AI that can act on the web."

### 2. Claude Code auto mode blocked its own cleanup during an attack
**What it is:** Security researcher Johann Rehberger published an attack against Claude Code's auto mode that works ~80% of the time. The attack tricks Claude Code into downloading a zip archive and executing a local file that imports `base64` — a common payload pattern. Most alarming detail: in several runs, Claude *detected* it was compromised and tried to terminate the malware process. Auto mode blocked the cleanup command. The safety classifier allowed the attack to start, then blocked the agent's attempt to stop it.

**Why it matters:** The "auto mode as safety layer" story Anthropic has been telling is now cracked. The failure mode isn't just "agent does something bad" — it's "the safety mechanism itself becomes part of the failure path." Willison's framing is the right one: the only actual protection for unattended agents is a sandbox (container/VM, restricted egress, no home directory or credentials in scope). Auto mode is a supplement, not a substitute.

### 3. AI agents are breaking the open-source security disclosure process
**What it is:** Cambridge CS professor Anil Madhavapeddy reports that within ~10 minutes of a security patch being shared for discussion, automated systems are probing for the vulnerability. rclone maintainer Nick Craig-Wood confirms: his project received 40+ security disclosures in one month versus ~20 in the previous 10 years — and GitHub CVE assignment has ballooned from 2-3 days to 3-4 weeks as the system is overwhelmed. The key mechanism: AI coding agents are now good enough at finding flaws that just *knowing a bug probably exists* in a given area is enough information to locate it.

**Why it matters:** The coordinated disclosure model (notify maintainer → wait for patch → public disclosure) was designed for a world where finding and exploiting a bug took days or weeks of human effort. That assumption is gone. The people actually running open-source infrastructure are dealing with this now — not as a future risk.

**Reel angle:** "The 10-minute embargo — AI agents are breaking how the internet protects itself from security bugs"
