## Top 3 Things Worth Paying Attention To

### 1. Haiku 5.5 makes the Opus-does-thinking / Haiku-does-volume split real and cheap

**What it is:** Anthropic launched Claude Haiku 5.5 on October 7, pricing it to match GPT-6 Luna exactly — $0.10/$0.50 per 1M tokens under 100K tokens, with a 5x jump above that threshold. It ships with a 1M-token context, effort controls (low/medium/high/xhigh/max), and is positioned explicitly as the subagent worker in multi-model harnesses: Opus or Sonnet does the thinking, Haiku runs the high-volume tasks (summaries, compaction, DB queries). AI News puts it plainly: "Opus does the heavy thinking, Haiku does the high-volume work." Cursor says it's "10x less" on shorter requests; Devin reports 58.4% on FrontierCode at roughly one-eighth the cost per task. Terminal-Bench went from 0% to ~33–39% (independent vs. Anthropic's own number). OSWorld (computer use) jumped from 15% to 72%.

**Why it matters:** This is the first time a capable small model is officially designed and priced for the subagent role inside multi-model loops. The practical unlock: you can now run a cost-sensitive version of Claude Code, Devin Fusion, or any agentic pipeline where the small model does the grunt work without the cost adding up. It also ships with adaptive thinking, so effort-level tuning on a cheap model is now something practitioners can actually use. Caveat from Simon Willison: prompts over 100K tokens pay 5x more, and heavy token use at max effort (~3x Luna) can erode the per-token savings — so long-context agentic loops need to watch their math.

### 2. The Claude SDK now has browser-use built-in — the action loop is gone

**What it is:** The same day as Haiku 5.5, Anthropic pushed a Claude SDK update that builds computer-use and browser-use toolsets directly into the Python and TypeScript SDKs. The SDK now runs the full action loop (clicks, keystrokes, navigation) against browser_use, Browserbase, E2B, or Daytona drivers. Developers no longer write that loop themselves — they pass the toolset and the SDK handles it.

**Why it matters:** Browser automation has been technically accessible for about a year now, but required wiring together the model API, a browser driver, and a custom action loop. That friction kept it in the "I could try that" bucket for most practitioners. Shipping the loop inside the SDK is the same kind of unlock that streaming being built into the SDK was — it moves from "plausible project" to "an afternoon." For Mansi's audience, this is the "First Step" story: people who know computer-use exists but haven't built with it now have a genuine entry point.

**Reel angle:** "Anthropic just removed the hardest part of building browser agents — here's what that actually means and what you can build now"

### 3. Cursor's new bots watch your code after you ship it

**What it is:** Cursor launched two production-facing bots: Rollouts and Security Reviewer. Rollouts monitors a deployment from PR to production — it builds a monitoring plan before merge, then watches live signals from Datadog/Grafana/Honeycomb post-ship and can auto-submit a revert PR if it detects a real regression. Security Reviewer scans code changes for injection flaws, broken auth, committed credentials, and dependency vulnerabilities, with severity ratings and one-click fixes. Both run as teammates alongside the existing coding bots. Average review time is reportedly down from 4.8 to 3.8 minutes; suggestion acceptance up to 60–70%.

**Why it matters:** This is the clearest example yet of AI moving from "helps you write the code" to "watches what happens after you ship it." The mental model shifts from AI as a pair-programmer to AI as an always-on teammate with different roles — one writes, one reviews, one watches production. That framing matters for Mansi's audience because it's a concrete answer to the question "what are AI coding tools actually doing that's different from autocomplete?"
